# Session du 2026-09-18 — tranche 7, fiche 0011

## Objectif

La tranche 6b livrée, Lucas a dit « on continue » : la suivante dans `status.yml` est la 7, le
connecteur MCP distant pour Claude Chat et Cowork, protégé par OAuth. L'issue #7 pose une condition
à toute implémentation : si OAuth exige de conserver des clients ou des jetons, une fiche tranche où
et comment, et elle est actée d'abord. Cette session établit les faits et écrit cette fiche.

## Actions

- **Relu à la source, non de mémoire** : la spécification MCP (autorisation, révisions 2025-06-18 et
  2025-11-25 ; transports Streamable HTTP), la documentation des connecteurs Claude
  (authentification, construction, authentification différée), les paquets du SDK TypeScript sur
  npm — jusqu'à extraire les archives `@modelcontextprotocol/server` 2.0.0 et `core` pour lire
  leurs signatures —, et l'API de contenu de GitHub.
- **Les faits qui commandent le choix** :
  - le serveur MCP est un *resource server* : métadonnées RFC 9728 **MUST**, 401 à
    `WWW-Authenticate: Bearer resource_metadata="…"` **MUST**, audience du jeton vérifiée **MUST** ;
  - le serveur d'autorisation : OAuth 2.1, métadonnées RFC 8414, PKCE `S256` annoncé, redirect URI
    comparées exactement, rotation des jetons de rafraîchissement pour les clients publics
    **MUST** ; l'enregistrement des clients se fait par CIMD (**SHOULD**), pré-enregistrement, ou
    DCR (**MAY**, « pour compatibilité ») ;
  - Claude, sur toutes ses surfaces dont Cowork : PKCE toujours, **une seule URL de rappel**
    (`https://claude.ai/api/mcp/auth_callback`), un **identifiant client pré-enregistré** saisissable
    dans les paramètres avancés du connecteur, rafraîchissement réactif avec rotation attendue,
    dix secondes de délai, plage d'adresses `160.79.104.0/21` ;
  - le SDK v2 (2.0.0, publié la veille, lignée stable) sert le MCP en Streamable HTTP par une
    fonction `fetch(Request) → Response` sans état, avec une garde Bearer à vérification injectée,
    et **ne fournit aucun serveur d'autorisation** ; son adaptateur Node dépend de Hono, inutile :
    h3 1.15, celui que Nitro exécute, expose `toWebRequest` et `sendWebResponse`, auto-importés.
- **Écrit la fiche [`0011`](../docs/decisions/0011-autorisation-oauth-du-connecteur-mcp.md)**,
  proposée : cinq options, dont une sous-option. Retenue pour validation : le dashboard est son
  propre serveur d'autorisation, pour un client pré-enregistré — Claude —, authentifié par la
  session GitHub existante ; jetons d'accès signés d'une heure, liés à l'audience ; jetons de
  rafraîchissement tournés, conservés par empreinte en SQLite (migration 3) ; codes d'une minute en
  mémoire. Le critère : la fermeture — un utilisateur, un client, une URL de rappel, connus
  d'avance.
- **Relevé un préalable** que la fiche consigne : le jeton GitHub de production est limité à la
  lecture des contenus ; l'écriture dans `docs/` exige le droit d'écriture des contenus sur
  cairn-wms.

## Décisions
